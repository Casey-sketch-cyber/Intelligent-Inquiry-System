# 独立虚拟机部署与验收

## 当前交付范围

办公电脑运行工作台和虚拟机启停器。QQ、IC交易网专用 Edge、数据库、回复解析及自动采集程序在配对 Windows 来宾中运行。使用 VirtualBox 的独立桌面来隔离鼠标键盘；不依赖 QQ 自身提供后台控件接口。

本次配置只读验收：禁止真实询价、回复和名片发送。Windows 安装、QQ/IC交易网本人登录、真实跨会话采集、连续运行与重启后复核仍需现场完成。尚不能据离线回归宣称真实业务已全部验收。

## 存储与安装

- 主机 VirtualBox：`D:\VirtualBox`。仅安装主体，不安装 Extension Pack、桥接和 USB 转发组件。Windows 必需的系统驱动/安装登记可能由系统放在系统目录；业务文件及虚拟磁盘不在主机 C 盘。
- VM 配置、安装材料、配对及共享队列：项目 `data/vm/`；VirtualBox 用户配置为 `data/vm/virtualbox-config`。
- 8GB 内存、4 vCPU；两块动态虚拟盘上限为 64GiB 系统盘 + 36GiB 数据盘。文件按实际使用增长，合计上限 100GiB，快照/安装镜像会额外占空间。
- 以上为创建默认值；本机在排查 Windows 安装停滞时暂调为 3 vCPU。核数调整不是通用修复，需通过完整安装、重启和持续运行验收。
- Windows 来宾系统盘为 C，询价应用和数据为 `D:\TianxinRuntime`。两块来宾磁盘都由主机 D 盘的 VDI 文件承载。
- 只共享 `data/vm/setup`（只读）和 `data/vm/bridge`（读写），不共享整个 D 盘。共享剪贴板、拖放关闭。

1. 从[微软官网](https://www.microsoft.com/zh-cn/software-download/windows11)下载「适用于 x64 设备的多版本 ISO」，选择简体中文，保存到项目 `data/vm/installers`。安装时按持有的授权选择版本。
2. 主机运行组件由 `vmhost/install_host.ps1` 安装：核对 Oracle 签名与官方 SHA256，只安装 x64 MSI，安装位置固定为 D 盘，不自动重启。需要用户在 Windows 管理员提示中授权。
3. 在项目 PowerShell 中先将 `TEMP`、`TMP`、`PYTHONPYCACHEPREFIX` 设为项目 D 盘缓存目录，再准备材料：

   ```powershell
   .\.venv\Scripts\python.exe -B -m vmhost.package --with-data --create
   .\.venv\Scripts\python.exe -B -m vmhost.package --with-data --iso 'D:\完整路径\Windows11.iso'
   ```

   已存在 VM 时 `--iso` 仅在正常关机状态挂载镜像；不会创建第二台或覆盖旧虚拟磁盘。`--with-data` 为**本用户迁移包**，包含历史数据库、设置、模型密钥和名片，不得给其他客户。默认不包含私有数据；目标目录若已有私有材料会拒绝当作公共交付包。

4. 双击 `启动独立运行环境.bat`，点击「查看登录窗口」，在虚拟机里安装 Windows。安装目标选 **64GB 系统盘（磁盘 0）**，36GB 数据盘先保留未分配。不要在办公电脑上运行 Windows ISO 中的安装程序。

   本机首次安装另提供 `python -B -m vmhost.install_windows` 准备 Windows PE 安装媒体，解决启动光盘按键确认容易错过的问题。它只接受已关机、挂载路径匹配且两块 VDI 都仍为空的专用 VM；运行中或写入过的磁盘会拒绝，不会断电或重装。当前模板已核对本次简体中文多版本镜像第 1 项为家庭版，换镜像前必须重新核对版本索引。模板只分区磁盘 0、安装 Windows；不建立用户、不设置自动登录、不代选隐私，也不加入绕过硬件检查的命令。产品密钥页可使用安装器自身的「我没有产品密钥」稍后激活；账号、隐私和登录由用户完成。
5. Windows 安装完成后，控制台点击「Windows 已装好，挂载辅助组件」，在虚拟机光驱内运行 `VBoxWindowsAdditions.exe`，完成后重启虚拟机。Windows 及驱动确认由用户处理。
6. 在虚拟机里访问 `\\VBOXSVR\TianxinSetup`，以管理员身份运行 `InstallGuest.cmd`。初始化脚本先核对 VirtualBox 产品名和配对硬件 UUID，再只初始化该 VM 专用的 36GB RAW 数据盘；磁盘布局不符则停止。已有运行目录不覆盖。
7. 初始化离线安装 Python 和已锁定依赖，使用 SQLite 一致性备份导入历史。不会复制原 QQ 或浏览器登录态。服务在该 Windows 用户登录后启动，不保存 Windows 自动登录密码。
8. 在虚拟机 D 盘安装 QQ，用户本人登录 QQ。登录窗口保持可操作；通过工作台打开 IC交易网专用浏览器并由用户本人登录。QQ 新登录可能需要同步历史，不能假设迁移数据库就能恢复所有客户端历史消息。

   本机部署材料中已放入经有效腾讯数字签名核验的 QQ 9.9.36 x64 安装器，来源为用户原有下载文件，复制后的 SHA256 再次一致。初始化清单也会校验该文件；不要把包含本用户迁移资料的整个 setup 目录分发给客户。

## Windows 安装进度不动时

先区分重启前的蓝色安装界面和重启后的黑色安装界面，它们的百分比不是同一阶段。不要只因数字几分钟不变就断电；结合 `VBox.log`、VM 进程负载和多次 `VBoxManage debugvm <UUID> statistics` 的系统盘读写增量判断。仍有读写时继续观察；CPU 持续忙碌本身不能证明安装在推进。

主机启用 Hyper-V/VBS 时，日志可能出现 `VT-x is not available` 并改用 NEM。[Oracle 故障排查文档](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/Troubleshooting.html)记录了这种组合的性能问题，官方仓库 [issue #799](https://github.com/VirtualBox/virtualbox/issues/799) 也包含 Windows/EFI 启动卡死、受虚拟处理器数量影响的复现。本机 2026-10-21 的 2 vCPU 冷启动停在 EFI，3 vCPU 能通过 EFI；这不能单独证明原先的 33% 安装停滞已修复，也不能推广为所有客户必须使用 3 核。

本机同轮验证中，3 vCPU 的新盘安装通过了重启后 33% 并到达 54%，但后续启动切换仍黑屏。保存新完整快照后冷启动现有系统盘，最终进入 Windows 首次地区设置。因此目前只确认安装已恢复到首次设置，正常重启及连续运行的稳定性尚未验收。

需要中断确认停滞的安装时，先保存并核实可回退快照和 D 盘磁盘备份，移出带自动分区答案文件的光盘，再操作目标 VM。若 Windows 随后报告安装意外中断、无法继续，应保留旧盘，在新建且逐一核对为空的专用虚拟盘上重试。不得绕过 `vmhost.install_windows` 的已写入磁盘保护，也不得默认关闭主机安全功能来解决兼容问题。

客户部署验收应包含主机虚拟化后端、完整 Windows 安装、多次正常重启和持续运行；“VM 正在运行”或能进入一次安装画面不等于环境已经可用。

## 日常操作

- 点击「启动运行环境」启动无主机可见窗口的虚拟机；若 Windows 尚未登录，需要「查看登录窗口」完成登录。
- 「查看登录窗口」先请求停止自动任务，等待执行锁释放，再展示虚拟机，便于用户处理 QQ、网站登录或异常。完成后分离虚拟机窗口、保持内部 Windows 登录，再点「启动运行环境」恢复自动采集。关闭窗口时不要选择关机或保存状态，除非准备停止业务。
- 虚拟机内不得锁屏/注销；程序仅阻止运行时空闲睡眠，不解除 Windows 安全锁屏。锁屏或安全验证会暂停桌面操作。
- 「停止询价并关机」先拒绝新任务、暂停剩余发件项、等待执行结束，再请求正常 ACPI 关机。状态显示「已关机」后，来宾的运行内存和 vCPU 调度才停止占用。磁盘文件保留。
- 来宾服务掉线、忙碌或未安装时，不会强行断电。需要在运行窗口里正常关闭 Windows。首次系统尚未安装时，请不要启动空虚拟机。
- 只关闭工作台网页不会关闭 VM。主机睡眠、关机时也无法继续自动询价。

## 通信和发送边界

控制台仅监听 `127.0.0.1`，从 8776 起避让端口；写接口要求同源浏览器请求。不会开放来宾 HTTP 端口，不需外部服务器、桥接或远程桌面。

共享文件中的请求/响应均带 HMAC、随机请求标识及期限。来宾先原子认领请求，再执行一次；处理中崩溃保留未知结果，恢复时返回待核实，不重放。主机超时也不自动重试写请求。

来宾模式由硬件 UUID 配对启用，宿主不能仅靠传入参数接管桌面。发送在 API 和 QQ 文字/图片/最终点击入口分别拦截。当前 `allow_send=false`，此设置不在网页开放。将来启用真实发送需另行授权和验收，供应商身份复核、发件箱幂等和限速仍保留。

空闲采集与发送流程共用排他锁，每轮最多补读一个已绑定会话，轮换处理。摘要不变不反复打开，读取失败退避，原文先落库再异步解析。无法看到的会话低频补收，无法确定的型号归属保留待确认，不声称图片或缺失历史已读全。

## 已有验收与下一步

离线回归覆盖签名校验、过期请求、崩溃不重放、只读发送拦截、物理机/错 VM 拒绝接管、逐家采集、下载转发、人工登录暂停、正常关机。浏览器验收覆盖待安装、连接/断线和只读状态。

真实 QQ 验收必须在 Windows 安装及本人登录后执行：保持主机其他软件在前台，连续记录主机前台/鼠标变化；对照 QQ 原始消息逐家核验已绑定会话；检查摘要未变时不重复点击、长回复与多型号归属、重启和断线后的状态。仍不得真实发送。

对外售卖前还需逐项验证目标 Windows/QQ/VirtualBox 版本、可交付安装流程、依赖补丁及授权条件。基础 VirtualBox 与 Extension Pack 的条款不同，本方案不安装 Extension Pack。每位客户单独配对、配置和登录，绝不分发本机 `data/`、`.env` 或预登录镜像。
