# 局域网双机部署与使用

办公电脑负责网页、型号搜索、批量任务、报价和回复建议；另一台 Windows 电脑作为 QQ 专用工作机，运行 QQ、IC交易网浏览器和回复采集。工作机需要桌面操作时使用自己的桌面，办公电脑不运行 QQ 自动化。两台都需开机并接入同一局域网。

常规双机工作流已接入，当前企业工作机按用户授权开放实发；新安装默认仍锁定。配对工作机暂停且空闲后，办公工作台的「开放常规实发」通过签名 RPC 持久化授权，绑定当前办公机和工作机设备，不能通过导入任意连接文件改变。DeepSeek 建议仍只供选择，不自动发送。

## 日常询价（2026-10-22 更新）

1. 第二台保持 Windows、QQ 和 IC交易网登录；从办公工作台点「恢复自动执行」，不用运行测试包。
2. 在本机「新建询价」逐行输入或批量粘贴型号、填写数量并预览话术。默认真实询价、每型号最多三家，家数可改。统一数量存在时，一整行中的空格属于型号，例如 `LPC2387FBD 100K` 会按 `LPC2387FBD100K` 和统一数量处理；显式两列用 Tab、逗号或冒号分隔。
3. 点击提交并确认后，批次与型号任务在第二台事务入库；界面立即显示「已排队」。后台串行执行，正在处理其他任务时仍可提交后续批次。提交标识相同且内容相同只建立一个批次，内容不同拒绝。
4. 达到本次家数上限、候选检查完毕或需要人工核实时，结束发信阶段，不再为了等待报价长期占用询价进程。历史询价绑定、消息和报告保留；不确定发送停止后续操作，不自动重发。
5. 发信后不自动核对回复，取消两小时窗口、五分钟核对和发信流程内的自动补收。本机外层顶部及内页顶部均固定显示「收集回复」「暂停收集回复」，不依赖正在浏览工作台还是型号列表。点击一次后，固定本次已发送并绑定会话的供应商列表，每条最多尝试一次；完成后停下，有失败则保留错误等待下次人工操作。暂停会中断当前读取并停止剩余列表，不暂停新询价。详情页可以只收集当前型号；新一轮需再点击，重启也不自动续收。
6. 网站要求验证码或登录时，批次显示「等待网站人工校验」，不再发起搜索。本人在第二台完成后恢复自动执行，队列保留原任务和已发送数量继续，已完成的批次不重新发送；不需要重新跑测试脚本。
7. 工作机重启后仍从办公端恢复；未开始的队列保留，正在发送的批次转为中断待核对，不默默重放。可在工作台取消排队批次，或对已停止/异常批次选择「继续未完成部分」；存在发送不确定项时拒绝自动继续。

本次新增 30 项场景（含复用的双机边界用例）与全套回归、真实浏览器流程验证；实体常规入口验证了接单、持久队列、验证码等待及取消，没有额外联系供应商。此前九条实体实发继续作为 QQ 发送证据，不能据此宣称常规流程已覆盖所有 QQ 或网站情形。当前网站仍需要本人完成验证码，不能绕过。

后续按用户要求改为手动单轮收集。旧 `enabled=true` 配置不再触发任何自动读取；收集请求有独立编号，重复点击不叠加队列。页面禁用缓存并更新脚本版本，旧窗口需刷新一次。网页状态刷新只查询数据库，不触发 QQ 读取。

在型号详情里选择建议或手动输入，再点「发送到 QQ」确认，回复才进入队列。只发送输入框中确认的正文，不自动加「关于型号：」前缀；型号与收件人通过系统内绑定保存。切换会话后资料卡可能晚于标题加载：身份核对只对缺失资料最多等待四秒，公司矛盾或会话变化立即停止，不用相似昵称跳过检查；回复仍核对原询价消息锚点。不确定发送不重发。已在实体工作机核验一条用户确认的跟进回复：系统成功记录与 QQ 中对应的唯一出站消息一致，未重新发送原询价。

## 第一步：在办公电脑准备安装包

当前开发电脑直接双击项目中的 `启动双机工作台.bat`。双机页面只监听本机，启动时不会启动办公电脑上的 QQ 执行器。原本机版本和旧虚拟机资料保留；这轮不继续安装虚拟机。

在页面的「生成工作机安装包」中生成部署包，或使用命令：

```powershell
.\.venv\Scripts\python.exe -B -m lanhost.package --with-data
```

输出在 `data\lan\packages`。勾选迁移或使用 `--with-data` 时，会备份当前业务数据库、设置、模型密钥和项目内名片，**只供本企业迁移**。不复制 QQ 或网站的登录状态。已有任务与回复通过 SQLite 一致性备份带到工作机，后续业务数据以工作机为准，不会自动同步回办公电脑旧库。

对外部署时先生成不含企业资料的办公电脑包：

```powershell
.\.venv\Scripts\python.exe -B -m lanhost.package --role office
```

客户在自己的办公电脑安装、配置后，再生成属于自己的工作机包。工作机包绑定生成它的办公电脑，不能把本企业的迁移包或配对文件分发给其他客户。同一安装包中断后可继续安装，已有业务数据和配对保留；不支持借此覆盖升级成其他版本。

## 第二步：在另一台电脑安装工作机

1. 将工作机 ZIP 复制到第二台电脑 **D 盘**并解压，再运行 `1_安装QQ工作机.cmd`。不要在办公电脑运行此包。
2. 安装器核对设备不同、文件校验和、Python/QQ 官方签名，使用包内依赖离线安装。Python 解压到 `D:\TianxinWorker\python-portable\3.12.10`，不调用系统 Python 安装器、不修改 Python 的系统注册或 PATH。工作目录固定为 `D:\TianxinWorker`；同包残留会验证后续装，其他设备/角色/版本或冲突文件会停止并保留。无需重装 Windows，不格式化磁盘。
3. 运行 `2_允许办公电脑连接.cmd`，由用户在 Windows 管理员提示中确认。规则只允许本程序、当前服务端口及专用网络中的本地子网，保留 Windows 防火墙。公司/家庭可信局域网需在 Windows 中设为「专用网络」；访客网络、AP 隔离或不同子网需由网络管理员处理。
4. 在工作机运行 `D:\TianxinWorker\data\QQ-install.exe`，选择 D 盘安装路径。如果已有 QQ，可先使用原客户端，但需核验版本兼容性和数据位置。**在 QQ 中把消息/文件存储目录也设到 D 盘并核对实际路径**；系统不会自动搬迁或删除 QQ 原有数据。登录原供应商会话所属的 QQ 账号，由本人处理验证码和登录确认。
5. 工作机页面点「打开 IC交易网登录」，本人完成网站登录。系统专用浏览器的配置、下载及缓存均位于工作机 D 盘。

安装脚本、业务数据库、模型配置、日志、依赖、浏览器和本程序临时目录均在 D 盘；Windows 必需的用户级启动/安装登记属于系统配置。QQ 客户端自身数据位置必须在这台实际电脑上确认，不能用离线测试替代。

工作机启动时默认暂停，不自动点击 QQ。安装后可用 `D:\TianxinWorker\Start.cmd` 重开状态页；关闭状态页不停止服务。程序在本人登录 Windows 后随登录启动，不保存 Windows 自动登录密码。

## 安装中断与旧包小修复

旧版显示 `Runtime already exists: D:\TianxinWorker` 只表示目录存在，不能据此判断安装成功。没有 `Start.cmd` 时应保留目录和 `data\logs\setup.log`，不要删除文件夹重来。

对已交付旧包可生成约 14MB 的修复包（包含便携 Python），无需再复制完整离线材料：

```powershell
.\.venv\Scripts\python.exe -B -m lanhost.package --repair-package <原安装包解压目录>
```

将修复 ZIP 中的「安装修复工具」文件夹放进第二台电脑原来解压的安装包目录，与 `application.zip`、`manifest.json` 同一层。进入「安装修复工具」运行「修复并继续安装.cmd」。工具只接受对应应用包，先备份原安装脚本和清单，再更新安装脚本后续装，不改原应用压缩包和迁移资料。

新版先验证离线材料，再创建运行目录；兼容旧包的中断现场，并记录安装阶段。配置和数据库只在缺失时初始化，用户编辑后的文件保留；仅未配对且配置仍与示例完全一致时，备份示例后导入迁移配置。已有配对复核后复用，已完成安装则直接打开，防止在运行中重复安装依赖。

修正了初始化命令未切换至安装目录而找不到模块的问题；文件摘要使用兼容 Windows PowerShell 5.1 的 .NET 实现。每轮新日志保存为 `data\logs\setup-日期时间.log`，不会覆盖旧日志。如果继续失败，应根据新错误和日志处理，不能仅凭原来的“目录存在”报错推断首次失败原因。

旧版出现 `Python was not installed in the D: runtime`，表示系统安装器返回后指定位置仍无解释器；仅凭该报错不能唯一确定注册冲突等原因。2026-10-22 改为附带 [Python 官方 NuGet 运行包](https://docs.python.org/3.12/using/windows.html#the-nuget-org-packages)，固定 3.12.10 x64、校验 SHA256 及解释器/DLL 的 PSF 签名。原来的系统 Python 和工作目录中的 `python` 文件夹保留；未配对且残缺/指向其他 Python 的 `.venv` 先备份到 D 盘再重建，已配对环境不自动搬动。没有调用卸载器或改写系统 Python 注册。

修复工具同样放回原安装包目录运行。新包应覆盖上一版「安装修复工具」文件夹，不应放入 `D:\TianxinWorker` 当作安装包。安装脚本会使用与当前 PowerShell 对应的内置模块路径，避免继承不同 PowerShell 版本的模块目录导致校验命令加载失败。

## 第三步：配对回办公电脑

1. 从工作机复制 `D:\TianxinWorker\data\lan\办公电脑连接.json` 到办公电脑的 D 盘。
2. 在办公电脑「双机工作台」选择这个文件，点「验证并连接」。验证当前办公电脑、独立工作机和专用证书后，才保存连接。文件包含企业配对凭据，请按私有配置保存。
3. 确认工作机 Windows、QQ 和网站均已登录，再点「恢复自动执行」。工作机需要保持桌面可操作；锁屏、退出 Windows、睡眠或 QQ 登录过期会影响收发。实发是否开放以顶部模式为准，未授权安装不会真实发送。

工作机地址改变时，在工作机页面点「更新连接文件」，重新复制并导入。服务端口因占用变化时，重新运行允许连接脚本。无需把服务暴露到公网，也不需要在办公浏览器忽略证书错误。

已导入连接后，短暂断线不会再返回首次安装页面。工作台保留当前型号页面与未提交草稿，顶部显示具体连接错误并自动重新检查；断线期间不能在保留的页面继续操作，恢复后可继续。也可点「立即重连」只检查状态；确实更换地址时再点「更新连接文件」。连接检查不重叠，也不会自动重提询价或消息。断线无法证明工作机任务已停止，应先确认状态。

通信时间戳按已核验的工作机时间生成，避免两台电脑长期时差超过三十秒后无法连接。办公端先核对导入的 TLS 证书与固定指纹，再通过只读 HEAD 获取该工作机的响应时间；旧工作机的 501 响应也可兼容，无需重新安装。校准信息仅缓存在当前进程中六十秒，使用单调时钟推进，不修改任一台 Windows 的系统时间。

网络等待预算与签名有效期仍分开：状态检查只等待五秒，签名至少有效三十秒，工作机继续校验一百二十秒上限、配对签名、证书和执行记录。校时失败不发送业务请求；工作机时钟突然变化导致请求被拒绝时，只清除校时缓存，不重放该请求，下次状态检查重新校准。两台 Windows 仍应正常同步时间，但日常时差不再直接阻断配对连接。

## 日常使用与故障

### 网站登录和验证码提醒

- 工作机需要登录 IC交易网或完成验证码时，办公端双机工作台显示对应提醒和网页截图。请到第二台亲自处理。工作台可启用桌面通知和提示音，是否弹出桌面通知取决于浏览器权限。
- 登录或校验解除后，提醒自动收起。队列沿用原任务继续执行。若先前手动暂停，请在办公端点「恢复自动执行」。
- 安装 T13 后，提醒中的「在这里处理」可打开工作机当前网页画面。你可以亲自在画面上点击或拖动。点击网页输入框后，可用面板的文字栏手动输入。页面跳转或画面过期时，先等待新画面，再决定下一步。
- 可在办公端「设置」的「网站校验群提醒」中保存企业微信群机器人的 Webhook 地址。默认关闭，同一次提醒只推送文字。移除地址后停止向群发送提醒。

- 办公电脑使用型号工作台，按型号检索、查看回复和 DeepSeek 建议；搜索、解析和 QQ 自动操作在工作机完成。常规实发开放后，确认提交的询价和手动回复由工作机执行。
- 工作机执行 QQ 操作期间应专用。人工登录或操作其他程序前先点「暂停自动操作」，等状态明确显示「已暂停」后再操作。显示「正在停止」时不要同时点 QQ。人工处理完再恢复采集。
- QQ 读取与任务执行共享同一个执行锁。后台采集一次最多补读一个会话，轮流推进，失败有退避；不是同时操纵多家公司。QQ 版本与历史是否完整仍需实际核验。
- 断线时先查看工作机和任务状态。请求先写执行记录，超时、进程中断或结果未知不会自动重发；不会靠断线重试反复执行业务操作。
- 通信采用导入的专用 TLS 证书和签名请求；更换工作机或证书后需重新核对配对文件。系统不修改 Windows 证书信任库。
- 备份运行中的业务库使用 SQLite backup。工作机故障或新电脑替换需要迁移配置与数据库并重新配对，不能直接复制旧设备身份文件。

## QQ 重装后的旧任务清理

重新安装 QQ 后，如果原会话记录没有迁入，旧任务的会话绑定无法凭空恢复。用户明确决定删除旧任务时，可以在第二台电脑运行独立的「清理旧询价任务.cmd」；工具包放在 D 盘解压，不需要覆盖或重装工作机。

工具先核对工作机设备和只读配置，通过本机页面暂停并等待空闲，再确认监听进程确属该 D 盘便携运行环境才停止服务。持有界面与执行两把锁后，先用 SQLite backup 保存完整数据库并校验，备份报告，再用事务清空任务、供应商、消息、报价、回复解析和发件箱。备份位于 `D:\TianxinWorker\data\backups\inquiry-reset-日期时间`；配对、账号配置、QQ/浏览器登录资料、请求执行记录及发送频率记录保留。旧报告复制校验后从当前报告列表移除。

清理包中的 `reset-request.json` 绑定目标工作机和当前任务快照（编号、型号、数量、创建时间）。任务发生变化或清理后再次运行会拒绝删除，防止误删后续新任务；该文件只含身份编号与摘要，不含配对密钥。清理后自动重启，核验任务数为零、保持暂停、真实发送仍锁定。办公电脑刷新即可；若实际端口发生变化，按工具提示重跑允许连接脚本并导入更新的连接文件。清理工具不自动创建或发送新询价。重启会终止旧解析线程，避免清空后 SQLite 复用记录编号导致旧结果混入新任务。

离线回归覆盖忙碌拒绝、完整备份、频率与配置保留、报告备份失败不删除、SQL 失败全事务回滚。`tests/history_reset_smoke.py` 另外在 D 盘隔离的便携 Python、原交付应用和真实 Windows PowerShell 5.1 中验证停服、备份、重启；它不接触实体工作机或 QQ。

### 三型号一次性实发送测试
